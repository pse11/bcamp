DI : Dependency Injection = 의존성 주입,
IoC 구현의 핵심 기술이라고 할 수 있다.

Dependency(의존성) : 객체가 협력하기 위해 필요로 하는 다른 객체
Injection(주입) : 이 필요한 객체를 내가 직접 만들지 않고, 외부(스프링)가 넣어주는 것.

=> 사용하는 객체를 직접 생성하여(new) 만드는 것이 아니라 컨테이너가 빈의 설정 정보를 읽어와 자동으로 해당 객체에 연결하는 것.

의존성 주입이 필요한 이유
예시 코드
public class PetOwner{
	private AnimalType animal;
    
    public PetOwner(){
    	this.animal = new Dog();
    }
}

interface AnimalType{}

class Dog implements AnimalType{}

class Cat implements AnimalType{}

이 코드에서 PetOwner 클래스의 생성자를 보면 animal 필드가 Dog타입으로 생성되는 코드가 있다.
만약 animal 필드가 Dog가 아닌 Cat으로 생성하려 하면 코드 자체의 수정이 필요하다.
이때 위와 같은 경우는 PetOwner 클래스가 AnimalType에 의존적이라고 볼 수 있다.
스프링에서는 의존성 주입을 통해 객체간의 의존성을 줄여준다.

의존성 주입이란 : 스프링 컨테이너에서 객체 Bean을 먼저 생성해두고 생성한 객체를 지정한 객체에 주입하는 방식이다.

의존성 주입 방식
1. Setter 메소드를 통한 의존성 주입
- @Autowired 사용
setter 메소드 위에 @Autowired 작성
- xml
<bean id="car" class="com.example.Car">
    <property name="engine" ref="engine"/>
</bean>

2. 생성자를 통한 의존성 주입
- @Autowired 사용
생성자 메소드 위에 @Autowired 작성
필드에 final 붙여서 불변성 보장할 수 있음(setter 사용못하게)
- xml
<bean id="car" class="com.example.Car">
    <property name="engine" ref="engine"/>
</bean>

3. 필드를 통한 의존성 주입
- @Autowired 사용
필드 위에 @Autowired 작성

이 셋중 요즘 권장하는 방식은 생성자 주입!!
