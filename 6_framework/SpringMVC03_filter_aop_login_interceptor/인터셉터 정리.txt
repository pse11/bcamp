웹 애플리케이션에서는 요청-> 컨트롤러-> 응답 이 흐름이 기본.

예를 들어
로그인 안 한 사용자가 /board/write같은 글쓰기 페이지에 접속했을때, 
로그인 안해도 들어가지는것을 막기 위해 인터셉터 사용

=> 요청이 컨트롤러로 가기 전에 걸러주는 장치가 있어야함. -> 이것을 도와주는 게 Spring 인터셉터.

전체 요청 흐름 정리(SPRING MVC 기준)
1. 브라우저에서 요청
2. DispatcherServlet(스프링 프론트 컨트롤러)
3. [인터셉터: preHandle()] <- 여기서 먼저 가로챔
4. controller 호출
5. [인터셉어: postHandle()]<- 컨트롤러 끝난 뒤에 실행됨
6. View 렌더링(JSP등)
7. [인터셉터: afterCompletion()] <-완전히 응답 끝났을 때 실행
8. 클라이언트로 응답 전송
